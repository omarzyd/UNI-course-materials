الـ Loop: كل الكورس variation على الصورة دي

الـ agent بيشوف الـ state، يختار action، والـ environment يرجّعله رقم (reward) وstate جديدة. وبعدين نفس الحكاية تاني. دوس "الخطوة الجاية" وتابع.

المثال ده من لعبة الكنز اللي هتلعبها في Lecture 2.

الصعوبة الحقيقيةالـ loop نفسه سهل. الصعب إن الـ reward اللي جاي دلوقتي ممكن يكون نتيجة action اتاخد من زمان. لازم الـ agent يعرف يوزّع الـ credit على الـ actions القديمة، ودي اسمها credit assignment.

يبقى RL شغلانة مختلفة عن الـ supervised learning اللي إحنا متعودين عليه. مختلفة إزاي بالظبط؟

5

إمتى RL يبقى الأداة الغلط

إنك تعرف إمتى متستخدمش method جزء من إنك تفهمها. أربع علامات حمرا:

  • عارف الإجابة الصح لكل input؟ يبقى عندك labels، استخدم supervised. أرخص وأسهل في الـ debugging.
  • الـ decision بتاعك مش بيغيّر اللي جاي؟ قرار واحد و feedback فوري يبقى bandit، وده أبسط بكتير من full RL.
  • الغلط وقت التعلّم غالي أو خطر، ومفيش simulator؟ الـ agent بيتعلم وهو بيغلط آلاف المرات. لازم تحدد هو مسموحله يغلط فين.
  • مش قادر تكتب reward تثق فيه؟ لو محدش عارف يقول يعني إيه "نتيجة كويسة"، المشكلة لسه مش جاهزة لـ RL.

جرّب: كل مشكلة دي تبقى إيه؟

الحالة الأخيرة فيها نقطة مهمة جداً: الـ reward نفسه. ده أخطر جزء في أي RL project.

جولة في الـ applications

كل application هنا اتكتب بنفس الطريقة: الـ action إيه، والـ reward إيه. اتعوّد تشوف أي مشكلة كده.

لو بصّيت عليهم كويس، هتلاقي النجاحات مش متوزعة بالعشوائي.

8

النجاحات بتتجمّع عند أربع شروط

  1. الـ reward ممكن يتقاس. click، score، survival flag. حد يقدر يحسب الرقم من غير خناق.
  2. الغلط رخيص، أو فيه simulator. الـ games والـ simulators بتخلّي الـ agent يغلط مليون مرة ببلاش. فريق الـ balloon عمل simulator للـ stratosphere الأول.
  3. الـ decision بيتكرر. ملايين visitors، آلاف games، control step كل كام millisecond.
  4. فيه interaction كفاية تتعلم منه. يا environment سريع، يا كومة كبيرة من logged decisions.

9

الخلاصة وراجع نفسك

  • RL للمشاكل اللي الـ feedback فيها بيقيّمك مش بيصحّحك، والـ score بيوصل متأخر، والـ actions بتاعتك هي اللي بتحدد الـ data اللي هتشوفها.
  • المجال كله loop واحد: state ← action ← reward ← تاني. الـ methods بتختلف في إزاي بتحوّل الـ loop ده لـ policy أحسن.
  • الـ reward function هي الـ specification. agent "فاشل" غالباً نجح في الحاجة الغلط.
  • فيه نجاحات حقيقية، وفيه كومة مشاكل method أبسط بيكسب فيها. اتعلّم تفرّق.
إيه الفرق بين feedback "بيقيّم" و feedback "بيصحّح"؟

اللي بيصحّح (supervised) بيقولك الإجابة الصح كانت إيه. اللي بيقيّم (RL) بيدّيك رقم على اللي إنت عملته بس: "7 من 10"، ومش بيقولك كان المفروض تعمل إيه.

مشكلة: جرعة insulin لمريض سكر كل ساعة. RL ينفع؟ إيه الـ state والـ action والـ reward؟ وإيه الخطر؟

state مستوى السكر دلوقتي، آخر أكل، آخر جرعة، الوقت. action الجرعة الساعة دي. reward مثلاً +1 لما السكر يبقى في الـ range الطبيعي، و penalty كبير لـ hypoglycemia.

شكلها RL: القرار بيتكرر، والجرعة بتأثر على الساعات الجاية. بس الغلط خطر جداً، فمحتاج simulator أو logged data زي الـ Sepsis.

اختيار الإعلان اللي يظهر لكل زائر لموقع. full RL ولا bandit؟

bandit. الإعلان اللي بتعرضه دلوقتي مش بيغيّر مين الزائر الجاي، فمفيش مستقبل تخطط له. أحسن action هو اللي الـ reward المتوقع بتاعه أعلى دلوقتي.

اكتب reward ممكن الـ agent "يغش" فيه.

مثال: لعبة سباق والـ reward على كل checkpoint بتعدّي عليه. الـ agent ممكن يلف حوالين نفس الـ checkpoints للأبد ويجمع points ومايخلّصش السباق. ده نفس منطق سلة الزبالة.

الـ Return: الهدف الحقيقي

Return Gt = مجموع الـ rewards من اللحظة t لحد الآخر، مش الـ step الجاية بس.

Gt = Rt+1 + Rt+2 + Rt+3 + …
Risky

G₀ = −5 + 0 + 10 = 5

Safe

G₀ = 0 + 0 + 0 + 0 + 10 = 10

القاعدةالـ agent هدفه يعمل maximize للـ return، مش لأي reward لوحده. +10 مغرية دلوقتي ممكن تبقى فكرة وحشة لو هتكلّفك −20 بعدين.

بس فيه حاجة ناقصة: في الـ Return ده، كنز بعد خطوة زي كنز بعد 100 خطوة. هل ده منطقي؟

6

الـ Discounting: الأقرب يسوى أكتر

عادةً بيهمنا الـ reward اللي بييجي بدري أكتر. في اللعبة كان مهم بس عشان الـ moves ممكن تخلص. الـ discounting بيحط التفضيل ده جوه الـ formula عن قصد:

Gt = Rt+1 + γRt+2 + γ2Rt+3 + … ,   0 ≤ γ ≤ 1

كل reward بيتضرب في γ أُس عدد الـ steps اللي قبله. حرّك الـ slider وشوف الأوزان بتعمل إيه:

0.90

الطريقين بالـ γ ده

مثال الـ lecture: +10 بعد move واحدة ولا +12 بعد 10 moves؟

  1. +10 بعد move واحدة: أول reward، فوزنه γ0 = 1، يعني 10 × 1 = 10.
  2. +12 بعد 10 moves: قبله 9 steps، فوزنه γ9. بـ γ = 0.9: 0.9⁹ ≈ 0.387.
  3. 12 × 0.387 ≈ 4.6، وده أقل من 10. يبقى الـ reward الصغير القريب كسب.
γ قريبة من 0

قصير النظر: الـ reward الجاي بس اللي فارق. لو γ = 0 يبقى Gt = Rt+1 بالظبط.

γ قريبة من 1

بعيد النظر: الـ reward البعيد يسوى تقريباً زي القريب.

γ = 1

ينفع بس لو اللعبة ليها نهاية زي الـ grid بتاعنا. غير كده الـ return ممكن يكبر لما لا نهاية.

لحد دلوقتي بنفترض إن الـ state الحالية كفاية عشان نتوقع اللي جاي. الافتراض ده ليه اسم، وهو اللي شايل الكورس كله.

الـ Markov Property: الحاضر كفاية

عشان تتوقع الـ move هتعمل إيه، محتاج الـ history كلها؟ ولا كفاية تعرف إنت فين، وفاضلّك كام move، وهتعمل أنهي move؟

S₀A₀S₁A₁…St−1At−1StAt⟶St+1, Rt+1 ?
P(St+1, Rt+1 | St, At, St−1, At−1, …, S0, A0) = P(St+1, Rt+1 | St, At)

يعني الـ state الحالية لخّصت كل اللي يهم من الماضي.

نقطة بيحبوا يسألوا فيهافي الـ grid، الـ state = المربع + الـ moves الفاضلة. اللي إنت اكتشفته عن الخريطة مش جزء من الـ state. ده "learning"، وده بالظبط شغل الـ RL algorithm على مدار games كتير.
ولو الافتراض ده باظ؟بنصلّحه بإننا ندخّل الحتة المهمة من الماضي جوه الـ state. مثال: DQN بيحط آخر 4 frames من اللعبة في الـ state، عشان frame واحد مش بيوضّح الكورة رايحة فين.

لو شيلنا الـ actions خالص وسيبنا states بتنتقل لبعض بالـ Markov property، يطلع أبسط model في الكورس.

8

الـ Markov Process: states من غير actions

sequence من states الـ state الجاية فيها معتمدة على الحالية بس:

P(St+1 | St, St−1, …, S0) = P(St+1 | St)

بيتوصف بحاجتين: set of states S وtransition matrix P (احتمال الانتقال من state لـ state).

S = Sunny وR = Rainy. خلي بالك: R هنا Rainy مش reward. هنحسب الـ transition matrix من الـ data خطوة بخطوة:

احسب G0 لو الـ rewards هي 2, 0, −1, 5 وγ = 0.5.
  1. الأوزان: γ⁰=1, γ¹=0.5, γ²=0.25, γ³=0.125
  2. اضرب: 2×1 = 2 · 0×0.5 = 0 · −1×0.25 = −0.25 · 5×0.125 = 0.625
  3. اجمع: 2 + 0 − 0.25 + 0.625 = 2.375
إيه معنى γ = 0؟ وليه γ = 1 مينفعش في task مالهاش نهاية؟

γ = 0: كل الأوزان بعد الأول بقت صفر، يعني Gt = Rt+1، والـ agent مش شايف غير الـ step الجاية.

γ = 1 في task مستمرة: بتجمع rewards للأبد من غير ما تصغر، فالمجموع ممكن يبقى ما لا نهاية، ومينفعش تقارن بيه.

في لعبة الكنز: هل "أنا عرفت إن (2,2) فيها فخ" جزء من الـ state؟

لأنه بيوصل مع الـ state الجديدة St+1 في الخطوة اللي بعدها. الـ trajectory: S0, A0, R1, S1, A1, R2, …

الطريق الـ risky والـ safe: فيه قيمة γ تخلّي الـ risky أحسن؟

لأ. الفرق = 10γ⁴ − (−5 + 10γ²) = 10γ⁴ − 10γ² + 5، وأقل قيمة ليه 2.5 (عند γ² = 0.5)، يعني دايماً موجب والـ safe دايماً أحسن. عشان كده الـ lecture استخدمت مثال +10 و+12 عشان تورّي إن الترتيب ممكن يتقلب.

الـ Return، وشكله الـ recursive

Gt = Rt+1 + γ Rt+2 + γ2 Rt+3 + … = Σk=0∞ γk Rt+k+1

وليه شكل تاني هنستخدمه في كل حتة:

Gt = Rt+1 + γ Gt+1

يعني الـ return دلوقتي = الـ reward الجاي + γ × الـ return اللي بعده. دوس واحسبها من الآخر لورا (rewards = 2, 0, −1, 5 و γ = 0.5):

γ صغيرة: الـ agent قصير النظر. γ قريبة من 1: بعيد النظر، بس غالباً أصعب في التعلم. ولو γ = 1 والـ task مش بتخلص (مثلاً أسهم بتلف في دايرة)، الـ return مش معرّف.

دلوقتي لو عندنا return، إيه اللي بيختار الـ actions؟ الـ policy.

9

الـ Policy: قاعدة الـ agent

π(a | s) = Pr{ At = a | St = s }

  • Deterministic: action واحد في كل state. أسهمك كانت كده.
  • Stochastic: احتمال لكل action. بنستخدمها في الـ exploration أثناء التعلم، ولما الـ agent مش شايف الـ state كاملة، أو بيلعب ضد حد.
  • في MDP شايف كل حاجة، الـ deterministic policy كفاية عشان توصل لـ optimal.
لخبطة شائعةالنرد مش جزء من الـ policy. النرد هو الـ environment (الـ dynamics). الـ policy هي اللي إنت كتبته: السهم.

هدف RL كله: لاقي policy بتجيب أكبر expected return.

وإزاي نقول إن policy أحسن من التانية؟ بنقيس قيمتها.

10

Value functions: v و q

قيمة الـ state
vπ(s) = Eπ[ Gt | St = s ]
الـ return المتوقع لو بدأت من s ومشيت بـ π.
قيمة الـ action
qπ(s,a) = Eπ[ Gt | St = s , At = a ]
الـ return المتوقع لو عملت a دلوقتي وبعدها مشيت بـ π.

والاتنين مربوطين:

vπ(s) = Σa π(a | s) qπ(s, a)

مثال: state فيها action واحد قيمته q1 = 5 وتاني q2 = 1. حرّك احتمال اختيار الأول:

0.70

ليه محتاجين q وعندنا v؟بـ q تقدر تختار أحسن action من غير ما تعرف الـ dynamics. وده سبب إن Q-learning بتشتغل بعدين.

والقيمتين دول عندهم علاقة بالجيران، زي ما حسبنا في المشهد الرابع. هي دي Bellman.

11

معادلة Bellman

ابدأ من التعريف، وعوّض بـ Gt = Rt+1 + γ Gt+1:

vπ(s) = Σa π(a|s) Σs′,r p(s′,r|s,a) [ r + γ vπ(s′) ]
Σ π(a|s)متوسط على اللي أنا ممكن أعمله.
Σ p(s′,r|s,a)متوسط على اللي العالم ممكن يعمله.
r + γ v(s′)الـ reward دلوقتي + قيمة اللي جاي مخصومة.

ده نفس اللي عملناه على المربع اللي فوق اليمين، بس بسهم واحد وγ = 1. وبيدّيك معادلة لكل state: n states يعني n معادلات وn مجاهيل.

نسخة الـ q

qπ(s,a) = Σs′,r p(s′,r|s,a) [ r + γ Σa′ π(a′|s′) qπ(s′,a′) ]

نفس الفكرة: قيمة الاختيار = reward دلوقتي + قيمة اللي جاي. هي أساس الـ dynamic programming الأسبوع الجاي، والـ temporal difference بعده.

نحلّها بإيدينا على مثال صغير.

حلّ vπ بإيدك: A و B

state-ين A و B، وγ = 0.5 و policy ثابتة. من A: نص احتمال نفضل في A بـ reward 0، ونص احتمال نروح B بـ reward 2. ومن B بنروح A دايماً بـ reward 3.

v(A) = 0.5 ( 0 + 0.5 v(A) ) + 0.5 ( 2 + 0.5 v(B) )
v(B) = 3 + 0.5 v(A)
  1. عوّض v(B) في الأولى: 0.75 v(A) = 1 + 0.25 (3 + 0.5 v(A)) = 1.75 + 0.125 v(A).
  2. 0.625 v(A) = 1.75 ، يعني v(A) = 2.8.
  3. v(B) = 3 + 0.5 × 2.8 = 4.4.
  4. تأكد: 0.5 (0 + 1.4) + 0.5 (2 + 2.2) = 2.8 ✓

الـ Optimal policy ومعادلة Bellman optimality

π أحسن من π′ لو vπ(s) ≥ vπ′(s) في كل state.

v*(s) = maxπ vπ(s)    q*(s,a) = maxπ qπ(s,a)
1optimal policy بتبقى موجودة دايماً في أي MDP محدود.
2ممكن أكتر من واحدة، بس كلهم ليهم نفس v* وq*.
3واحدة منهم على الأقل deterministic.
v*(s) = maxa Σs′,r p(s′,r|s,a) [ r + γ v*(s′) ]
q*(s,a) = Σs′,r p(s′,r|s,a) [ r + γ maxa′ q*(s′,a′) ]

الـ max بيخلّي المعادلة nonlinear، فمش بنحلّها زي مثال A و B. دوس على مربع وشوف قيمة الأسهم الأربعة محسوبة من جيرانه:

أخطاء شائعة لما بتكتب MDP

  • الـ state ناقصة حاجة الـ agent محتاجها، فمش Markov.
  • الـ reward بتدفع على خطوة بدل الهدف، فالـ agent يلاقي shortcut.
  • الـ reward بتيجي في الآخر خالص، فمفيش حاجة يتعلم منها بدري.
  • الـ task مالهاش نهاية وγ = 1، فالـ return ممكن يبقى infinite.
  • الـ action space ضخم (مثلاً layout كامل مرة واحدة) وكان ممكن يتقسم لاختيارات صغيرة.
  • الـ indexing غلط: الـ action في الوقت t بيجيب Rt+1.

جرّب: كل جملة فيها غلطة واحدة، هي أنهي؟

الـ episodic بتخلص، فالمجموع محدود. الـ continuing مش بتخلص، فمع γ = 1 المجموع ممكن يبقى infinite ومنقدرش نقارن. γ < 1 بيخلّي المجموع محدود (أقل من Rmax/(1−γ)).

ليه q* أنفع من v* لما منعرفش الـ dynamics؟

بـ v* عشان تختار action لازم تحسب Σ p [r + γ v(s′)]، يعني محتاج p. بـ q* بتاخد argmax على الـ actions مباشرة.
